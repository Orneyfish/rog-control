ROG Control: the look the Rust rewrite must match

These are real captures of the current Python app (main.py at commit 509d5e4) on the target machine, taken with harness/shoot_ref.py. The Rust windows must reproduce them: same layout, order, labels, icons and colours (the colours come live from ~/.local/state/caelestia/scheme.json, so hue follows the wallpaper; live values such as temperatures, RPM and the highlighted option follow the hardware).

Responsive note: these are fixed-size desktop GTK windows, not web pages. There is no 390px layout; the images only scale down here so the page is readable on a phone. Window sizes to match (this machine): main 494x913, Fans and Power 560x760, Keyboard Lighting 380x480, Extra 453x320, each within 4px.
States not captured here, defined by main.py:
  • Error: a failed hardware write shows an Adw.Toast at the bottom of the window with the tool's error text; the control stays visible.
  • Confirm: changing the MUX (Ultimate) asks for confirmation before anything is written and offers a reboot; the dialog is an Adw alert on the main window.
  • Loading / unavailable: controls the firmware reports unavailable (PL1/PL2, dynamic boost, temp target, NVIDIA offsets and power limit) are still shown and interactive; availability only seeds starting values and an informational note.
  • Tray: no window at boot; the only thing visible is the tray icon (rog-control-symbolic).
